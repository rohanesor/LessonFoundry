# Recorded evaluation

## Environment and scope

Local Python 3.14 / Node 22, FastAPI, SQLite test adapter, Next.js and Chromium.
Mock LLM and avatar providers were explicitly enabled. No paid-provider credentials
were available. These results verify control/state behavior, not live AI correctness.

## Automated backend tests

`PYTHONPATH=backend .venv/bin/pytest backend/tests -q`: **16 passed**.

- Fresh pack schema, evidence and locations.
- Single-question regeneration preserves approved neighbors.
- Approval locks and student response allowlist.
- A new draft preserves the previous published version.
- Source changes mark old assets stale and remove them from student eligibility.
- An unsupported objective is excluded from generation.
- Provider exceptions leave the existing pack unchanged.
- Optimistic edit conflict and malformed key block.
- Cross-pack/invented evidence rejection.
- Authentication and ownership checks.
- Approved-script requirement for mock video.
- Cancelled jobs do not run.
- Suspicious instruction echoes block approval (not a comprehensive injection test).
- DOCX and PPTX extraction retain paragraph and slide locations.
- Approval rejects an asset version changed since the teacher opened review.
- Answer key retains the published version while a new draft is in progress.

## Browser tests

`npx playwright test`: **2 passed**.

1. Real API-backed demo setup, evidence drawer, Q3 v2, Q1/Q2 unchanged, timeline,
   explicit teacher review, locked approval, student practice and server-side checking.
2. Fresh pack creation through UI, real text-file upload, gap check, generation,
   screen navigation, approved-script mock rendering and 820px tablet viewport.

Both tests assert no uncaught JavaScript page errors or console errors. Screenshots in `docs/evidence/`
were generated by the browser tests—not screenshots of the supplied static prototype.

Chromium initially could not start because this machine lacked libnspr4/libnss3.
The packages were downloaded and extracted to a temporary directory without changing
system packages, and tests ran with that directory in LD_LIBRARY_PATH. Other machines
can use Playwright's documented `install --with-deps chromium` setup.
